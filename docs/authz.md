# Авторизация и проектный доступ

## Основные правила

- Незарегистрированные пользователи не имеют доступа к доскам, задачам, API,
  realtime и вложениям.
- После регистрации пользователю автоматически создаётся личный workspace, где
  он является `WorkspaceMember.ADMIN`.
- Членство `WorkspaceMember.MEMBER` само по себе не открывает проекты.
- Доступ обычного участника определяется активной записью `ProjectMember`.
- Глобальный администратор и `WorkspaceMember.ADMIN` видят все проекты
  соответствующего workspace.
- Просроченный `ProjectMember.expiresAt` не даёт доступ и workspace исчезает из
  переключателя, если других активных проектов в нём нет.

## Проектные роли

| Действие | VIEWER | MEMBER | ADMIN |
| --- | --- | --- | --- |
| Читать проект и задачи | да | да | да |
| Читать вложения | да | да | да |
| Создавать и изменять задачи | нет | да | да |
| Комментировать | нет | да | да |
| Менять исполнителя, статус и приоритет | нет | да | да |
| Управлять участниками проекта | нет | нет | да |
| Архивировать проект | нет | нет | да |

`WorkspaceMember.ADMIN` не требует отдельных записей `ProjectMember`.

## Приглашения

- Приглашение всегда относится к одному проекту.
- Ссылка действует 7 дней.
- В приглашении задаются роль `MEMBER`/`VIEWER` и необязательная длительность
  доступа.
- Длительность доступа отсчитывается с момента принятия приглашения.
- Повторное принятие не понижает существующую роль и не сокращает действующий
  срок доступа.

## Публичный приём багов

Публичная доска отсутствует. Если понадобится анонимный приём багов, он должен
быть реализован отдельной формой, которая позволяет только создать новую заявку
и не раскрывает проекты или чужие задачи.
